04 · Hosting and placement

Three machines, each with one job

Workload labels pin every service to a node. Compare the repository's v2 target with the five-node baseline that was last deployed.

Quorum is not HA. Three managers keep the Swarm control plane alive through one node loss. GitLab, PostgreSQL, Keycloak, Traefik, Backstage and observability still run as single instances that are recovered, not failed over.

05 · Infrastructure contract

Pick a provider once. Everything downstream stays the same.

Each provider has its own Terraform root and emits the same normalized infrastructure output. DNS, inventory and bootstrap never branch on provider name.

No runtime selectorThere is no infrastructure_provider variable, no cross-provider Swarm and no automatic failover. The operator chooses a deployment root before plan.
Backups are a separate choiceAny compute provider can back up to Hetzner or OVH Object Storage through the same generic S3 inputs.
State stays sovereignTerraform state lives in an S3-compatible bucket with lockfile locking, created outside the root's own lifecycle (ADR 0013).

06 · Bootstrap and GitOps handoff

Why the order matters

SwarmCD reads from GitLab, so GitLab cannot be managed by SwarmCD on day one. Ansible builds everything SwarmCD depends on, proves the images exist, and only then hands over.

    08 · Ingress, identity and access

    One front door, several ways through it

    Traefik terminates TLS for everything. What happens next depends on who is calling: a person in a browser, GitLab's own login, or a machine with a token.

    10 · Observability

    Services inherit telemetry by being deployed

    A service's metrics path is part of its intent and is rendered into Prometheus file discovery. Logs are collected from every node. Neither Prometheus nor Alloy mounts the Docker socket.

    Edge protection: CrowdSec parses Traefik access logs in observe-first mode. No bouncer middleware enforces its decisions yet.

    11 · Backup and disaster recovery

    Encrypted, node-local, application-consistent

    Systemd timers on the nodes that own the data produce backups, encrypt them with age and upload them to an independent S3-compatible bucket. A passing repository check is not a restore.

    Backup

    1. GitLab backup artifactVM-01 timer, dedicated GitLab volume
    2. Platform database dumpVM-02 timer, Backstage and Keycloak data
    3. Platform and observability datavolume data on the platform node
    4. Encrypt and uploadage-encrypted, retention applied, S3 bucket

    Restore

      15 · Portability and scope

      Small now, with a clear path to Kubernetes

      Every Swarm primitive used here has a direct Kubernetes counterpart. Terraform keeps provisioning infrastructure either way.

      Deliberately out of the first v2 MVP

      Kubernetes migrationArgo CD / FluxDistributed storage HA PostgreSQL, GitLab, identityMulti-region active/activeNAT gateway VaultTempoSeparate monitoring cluster

      Proposed next boundary

      A developer VPN with a private ingress listener for designated HTTPS routes. It must never expose Swarm management ports, Docker sockets, database networks or raw overlay addresses. Hostname, cookie scope, device enrolment and recovery need decisions first.

      Self-hosted end to end, recoverable by design

      Source, CI, registry, identity, portal, telemetry and backups all run on infrastructure you choose. The remaining work is proof: live commissioning, a timed restore drill and the first service shipped through the golden path.
